# 授信周报

全程脚本，不需要模型改数据。额度由用户直接在授信一览表里更新，周报里的额度部分由公式自动关联，脚本只负责归档、拆表、转数值和出 PDF。

## 前置

- macOS、Node.js 20+、Xcode 命令行工具（`swiftc`，首次运行把 `scripts/render.swift` 编译到系统临时目录）。PDF 由脚本用 macOS 自带的 CoreGraphics 直接绘制，不需要 Excel、LibreOffice 或其他 PDF 工具。
- 工作目录：默认 `~/Library/CloudStorage/OneDrive-个人/东方财富/授信/授信周报`，其下有累计簿 `证券公司授信周报.xlsx` 和各日文件夹。用 `--root` 或 `CREDIT_WEEKLY_ROOT` 覆盖。
- 输入文件须含「授信一览表」「授信周报」两个 sheet，且周报里有「银行性质」表头。

## 步骤

1. 确认用户给的 xlsx 路径。先预检，看报告日、各输出路径和两页打印范围：

   ```sh
   node <本skill目录>/scripts/run.mjs <xlsx> --dry-run
   ```

   报告日默认取授信周报 E1 的日期，与用户说的周报日期不符时用 `--date YYYY-MM-DD` 指定。

2. 执行：

   ```sh
   node <本skill目录>/scripts/run.mjs <xlsx> [--date YYYY-MM-DD]
   ```

   脚本依次：
   - 把输入文件拷进 `<root>/<YYYYMMDD>/`（已在该目录则不拷）。
   - 导出 `证券公司授信一览表-YYYY.MM.DD.xlsx`：只含授信一览表，同表公式保留，引用债券投资余额、授信周报等其他 sheet 的公式转成数值，批注保留。
   - 授信周报转数值（公式去掉、保留当前值和格式），以 `YYYY.M.D` 为名放到累计簿最前面；同名 sheet 已存在则原位替换，可安全重跑。
   - 导出 `证券公司授信周报YYYY.MM.DD.pdf`：A4 纵向、0 边距、水平垂直居中、共两页，每页各自缩放到一页，隐藏行不打印。分页按内容判断：第二页从「银行性质」表头起，到额度明细的最后一行（B:F）；第一页是表头以上最后一个可见内容行以前的周报正文（B:H）。没有写死行号。

3. 汇报实际结果：报告日、归档目录、导出的三个文件、累计簿新增还是替换、转数值的公式个数、PDF 页数。出现错误时如实转述，不绕过校验，不手改文件重试。

## 边界

- 脚本改写的只有累计簿 `证券公司授信周报.xlsx`（先备份，再写临时文件，校验 XML 合法后原子替换），其余文件覆盖同名输出。不删除任何文件。
- 缺授信一览表或授信周报、E1 不是日期（需 `--date`）、找不到「银行性质」表头、累计簿正在 Excel 里打开（存在 `~$` 锁文件）、遇到不认识的数字格式，脚本都会停止并报错。
- 改写累计簿前，上一版自动备份为同目录的 `.证券公司授信周报.xlsx.bak`（单份滚动，同一周重跑会覆盖它）。
- PDF 的字体用 macOS 自带的宋体和苹方替代原字体，列宽、行高、填充、边框、合并和分页按工作表原样排布，字形略有差别（也不是 Excel 自己导出的 PDF）。条件格式只支持周报用到的几类，不认识的会在 stderr 提示并跳过。
- 周报内容、额度和授信进展由用户在 Excel 里维护，不由脚本或模型修改。

## 自测

`node <本skill目录>/scripts/selftest.mjs` 离线运行，用合成工作簿验证拆表、转数值、样式并入、分页、版面和 PDF 页数，不写用户目录。
