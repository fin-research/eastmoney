# 测试规范

测试保护可观察行为、业务口径和信任边界。覆盖率用于定位漏测，不证明实现正确。

## 分层

- 纯函数：用少量有业务含义的输入验证数值、日期、排序、缺失值和时序隔离。期望值不复制生产算法。
- API、存储与服务绑定：验证公开 DTO、状态码、幂等性、事务和必要副作用。下游失败、凭据脱敏、访问拒绝和未来数据隔离属于必要边界。
- UI 状态：DOM 测试负责输入保留、保存结果、交互和生命周期。真实浏览器截图负责布局、字体、图表和响应式。截图不覆盖登录、数据库和线上接口。
- 架构守卫：静态扫描只用于明确的架构不变量，例如跨服务访问和业务组件复用。CSS 值、文案、import 拼写和控件总数用渲染测试验证。
- 同一抽象层的等价输入用代表值或参数表。重试时钟在拥有重试逻辑的测试中控制，调用方不真实等待。Prompt 测试保护版本、Schema、证据和关键业务约束，不锁定润色文案。

## 覆盖率

- 记录命令、源码范围和未执行层次。
- Node 内置 coverage 只统计已加载的 TS/JS。Vitest 的 include 和 Python source 会把未执行源码计入分母。gcov 的行与分支口径不同。不同工具的总百分比不可比较。
- Svelte 编译产物、第三方头文件和测试夹具不计入业务覆盖率。
- 覆盖率低时，先检查业务路径和断言质量，再补能阻止实际回归的最小用例。设门槛须固定分母并随业务评审。不要随失败降低阈值或自动更新截图。

## 清理

删除或合并低价值测试时，说明原保护目标和替代验证。未替换的源码检查是过渡守卫，不等于视觉或端到端保障。

## CI 范围

PR 标签 `ci:gateway`、`ci:dashboard`、`ci:data`、`ci:messenger`、`ci:ingest`、`ci:quant`、`ci:all` 声明要运行的项目，取代路径推导的依赖扩展。合并队列读取同一 PR 的标签。增删标签会重新触发 PR CI。无标签时按 `scripts/ci/affected.mjs` 的路径规则。公开安全、gitleaks、依赖检查和 CI 脚本测试始终运行；改动 `.github/`、`scripts/` 或依赖文件时标签无效。

合并队列不重复PR已通过的检查：PR的 `Monorepo CI` 通过后记录被测树（artifact `ci-tree`，含树和已测项目），队列提交的树相同且PR已测过队列所需的全部项目时，队列不再运行检查。Dashboard完整检查（单测、构建、视觉回归）在PR里运行。`main` 已前进、树不同、PR无通过记录或查询失败时，队列跑全量。

PR开启或转为Ready后，`automerge.yml` 启用自动合并（squash）；必需CI通过后PR自动进入合并队列。需要暂停时保持Draft或取消自动合并。
