# 测试规范

测试应保护可观察行为、业务口径和信任边界。覆盖率用于定位漏测，不用于证明实现正确，也不为提高数字重复断言。

## 分层与取舍

- 纯函数：用少量有业务含义的输入验证数值、日期、排序、缺失值与时序隔离。不复制生产算法计算期望值。
- API、存储与服务绑定：验证公开 DTO、状态码、幂等性、事务与必要副作用。下游失败、凭据脱敏、访问拒绝和未来数据隔离属于必要边界，不能作为“过度防御”删除。
- UI 状态：已有 DOM 测试负责输入保留、保存结果、交互与生命周期。真实浏览器截图负责布局、字体、图表与响应式。截图通过不代表登录、数据库或线上接口通过。
- 架构守卫：静态扫描仅用于明确架构不变量，例如禁止跨服务访问、业务组件复用规则。不要用源码中的 CSS 值、文案、import 拼写或控件总数代替渲染测试。
- 对同一抽象层的等价输入使用代表值或参数表。重试时钟在拥有重试逻辑的测试中控制，调用方不重复真实等待。Prompt 测试保护版本、Schema、证据与关键业务约束，不逐句锁定润色文案。

## 覆盖率的解释

报告必须记录命令、时间、源码范围及未执行层次。Node 内置 coverage 只统计加载过的 TS/JS。Vitest 配置的 include 与 Python source 会把未执行源码计入。gcov 的 C++ 行与分支口径也不同，不跨工具比较总百分比。Svelte 编译产物、第三方头文件和测试夹具不作为业务覆盖率。

不预设全仓 100% 或以低覆盖为由移除重要模块。先检查低覆盖的业务路径和已有断言质量，再补最小能阻止实际回归的用例。确需门槛时，必须明确稳定分母，随业务演进评审，禁止随失败降低阈值或自动更新截图。

## 清理与验收

删除或合并低价值测试须说明原保护目标和替代验证。不能仅因测试失败而移除。未替换的源码检查保留为过渡守卫，不能声称已获得视觉或端到端保障。
