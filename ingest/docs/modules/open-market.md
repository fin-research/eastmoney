# 公开市场操作播报

Messenger 的定时调用在周一至周五交易日北京时间 09:20 创建并执行 `omo` / `OmoWorkflow`，日实例为 `omo-YYYY-MM-DD`。不提前创建实例，也不用 `sleepUntil`。手动指定日期的实例立即执行。`ingest_cron_started` 和 `omo_bulletin_attempt` 日志记录计划时间、实际时间与延迟。

Workflow 有两个顺序 step：

1. `获取并清洗央行投放公告`：经 DATA / InternalData 取当日“经济数据&政策”资讯。复核上海日期、标签和标题前缀“中国央行”，不按重要性筛选。正文不要求含净投放/净回笼。
   - 删除投标量、中标量金额分句，并截掉“据DM数据显示”（兼容“DM数据显示”）及之后的文字。
   - 验证剩余投放操作及金额。“逆回购操作量为零”按零投放计算。正文明写“今日暂无/无逆回购到期”时，把该证据存入第一步结果，不拼接原文尾部的净投放金额。
   - 无匹配正文即抛错。
2. `查询到期回笼并生成播报`：请求 `/data/omo?startDate=当日&endDate=当日`，只汇总到期回笼。用正文投放金额减到期量，得到净投放或净回笼，零净额表述为持平。
   - 金额统一为亿元，兼容到期量的负号与正数表示。期限用明确中文。到期明细不显示零金额项，到期总量为零时表述为无到期。API 的其他投放项不替代新闻正文，也不混入总投放。
   - 空响应、跨日数据、到期金额或期限缺失视为失败，不填零。
   - 接口无到期记录时，满足三项才生成“今日无逆回购到期”：第一步有明确的当日无到期证据；接口全是有效逆回购投放；投放总额与正文一致。缺证据或金额不一致则重试。正文称无到期但接口有非零到期记录，也重试。接口显式的零金额到期记录可正常使用。

两个 step 都用 `retries: { limit: 20, delay: "15 seconds", backoff: "constant" }`，即首次执行后最多重试 20 次。没有循环或 sleep step，也没有运行时段截止，延迟启动、09:25 后发布的正文和手动按日期运行都正常执行。

每次请求最长 10 秒，耗尽重试后失败。只有日期参数无效时才抛 `NonRetryableError`。第二步重试时复用已完成的第一步。

返回日期、`status=found`、正文 `text`、文章 ID 和第一步尝试/失败次数。Messenger 消费 `text`。Workflow 内没有通知调用，平台成功与失败事件由 Messenger 统一投递。
