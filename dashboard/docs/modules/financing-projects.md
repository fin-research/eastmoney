# 融资项目

入口：`/financing/projects、/financing/projects/[id]`。公共规则见 [文档分流](../../AGENTS.md#context-routing)。仅在任务涉及本模块时读取。

## 业务：融资项目与 SOP

- 融资项目独立于负债记录。项目创建、修改和删除不读取、绑定或修改存续负债。
- 项目维护名称、融资品种、规模、负责人、状态、说明和单一“计划簿记”日期。
- 创建项目时选择启用 SOP。计划簿记日写入 `planned_issue_date`，作为 SOP“计划发行当日”的相对日期锚点。
- 项目起始日由最早任务启动日（时段）或计划时点自动推导，不晚于计划簿记日。任务增改后同步重算。
- 任务 `schedule_type` 区分 `point` 与 `period`。时段须同时有启动日和完成日且启动不晚于完成。时点允许待安排。历史任务保留原始开始日，但默认按时点解释，不把旧版统一填入的项目起始日当作节点真实启动日。
- 新建项目逐节点生成起止日期。修改计划簿记日时，SOP 时段的两端按相同自然日差平移，保留人工调整和区间长度。独立新增任务不平移。原零偏移时点仍固定到计划簿记日。
- 项目详情可将已有任务切换为时段并维护起止日期。本人任务办理仍只能更新本人任务状态。
- 删除项目时在一个事务中同步删除项目任务及其提醒记录。重复删除按幂等成功处理。
- SOP 节点顺序具有业务含义，拖拽排序必须作为一个原子动作提交。
- “项目管理”允许新建和维护项目及全部任务。“SOP 与提醒”允许维护 SOP 模板、节点与提醒规则。
- “本人任务办理”只允许更新 `assignee_id` 等于本人 `personId` 的任务节点状态，不得同时变更负责人、截止日或其他字段。

## 业务不变量

- 项目：`planning`、`in_progress`、`at_risk`、`completed`、`cancelled`。

- 项目任务：`not_started`、`in_progress`、`blocked`、`completed`。

- 提醒发送：`pending`、`sent`、`failed`。

- 业务“今天”按 `Asia/Shanghai` 解释。

- 甘特范围由今天、项目计划簿记日和节点日期共同决定，并扩展到完整月份。

- mutation 成功后只合并服务端确认的实体。失败时保留输入，不回滚到旧页面快照。

## 页面：Project and Gantt

- 项目信息、状态和时间轴保持清晰层级。
- 时间范围由上海时区当天、计划簿记日和节点日期动态覆盖，并按完整月份扩展。
- 甘特图中时段显示区间条及起止日期，时点显示日期标记，待安排任务不伪造区间。项目条覆盖全部任务起止日。
- 月、季刻度、项目条、节点条和“今天”线使用同一百分比时间轴。禁止硬编码年月或位置。
- 移动端优先使用项目卡片，不强行压缩完整甘特图。

## 路由与增量动作

项目列表与详情分别在 `src/routes/financing/projects/` 和 `[id]/`。`/financing/projects/options` 只在表单打开时读取选项。自动保存共用 `src/lib/financing/auto-save.ts`。创建和删除仍显式提交。普通 mutation 返回单一确认实体或删除 ID，就地合并，仅在需要时失效 `financing:reminders`，不得重读全页。

## 创建表单

新建项目使用 Superforms 和 `src/lib/financing/project-form.ts` 的 Zod schema 做客户端与 named action 双重校验。名称、SOP、有效计划簿记日期为必填。规模允许空值或最多八位小数的非负亿元值。校验失败保留草稿并定位错误字段。权限、SOP/负责人查询与写库仍只在服务端执行。其余表单继续使用原生 SvelteKit forms 与已有增量动作。
