# 授信工作台

入口：`/credit-workbench`。公共规则见 [文档分流](../../AGENTS.md#context-routing)。

## 按日截面与存储

Worker 通过 `HYPERDRIVE` 访问 Neon `credit` schema，migration 只放 `credit-migrations/`。

- `credit.institution` 保存单一当前状态：稳定 `id`、名称、机构性质、保密协议、银行经办机构、我司申请部门、我司经办人和债券投资偏好。修改直接更新该行，历史报告同样显示当前资料，不为元数据追加授信历史。
- `credit.metric(id,name,type)` 定义业务字段，`type` 为 `num/date/text`。`status` 仍是文字类型业务字段，供无到期日机构保留底层审批状态。不放入机构元数据。
- `credit.entry.verified` 为机构在精确报告日的人工定稿标记，同日所有字段保持一致，默认 false。未传入时保留当日标记，不跨日继承。
- `credit.entry` 是唯一运行时授信事实表，联合主键为 `(report_date,field_id,institution_id)`。`v_num/v_date/v_text` 必须且只能填写一项，并与 metric 类型一致。金额精度六位，额度非负，债券二级净余额可以为负。保留来源的创建日期、创建人和修订时间，历史作者未知时留空。
- `credit.entry_as_of(date,names)` 用 `DISTINCT ON (institution_id,field_id)` 按 `report_date DESC` 取截至所选日的最新值，再关联当前机构资料。零和空字符串均是有效值，输入 NULL 表示未修改。金额取消填 0，文字清空填空字符串。首个记录日起任意自然日均可查询，默认上海时区今天。
- `credit.append_entry` 在同一授信写锁和事务中更新机构资料、比较归一后的业务值并写 entry。同日同字段直接更新，不增加版本表。历史补录向后继承，后续明确字段覆盖补录。起止日期组合校验所有受影响的后续日期，撤销哨兵日期除外。
- `event` 使用 enum：`maintenance/new/renewal/increase/revocation`。同机构同日各字段的事件统一合并。撤销、首次新增、扩额依次优先，维护不降级已有事件。查询按机构、日期、事件去重，一次操作修改多个字段也只有一条申请事件。到期仍在视图按期限生成，不写事件事实。
- `total` 为总额。四项额度、债券/其它说明、法透/其它人工已用、二级买卖净余额、起始日、到期日、额度描述和备注均为 metric/entry。历史台账债券已用只供对账，融资派生已用仍从融资台账读取。

### 历史修订与切换

跨业务日不删除或直接更新 entry。普通 UPDATE/DELETE 由触发器拒绝。受控历史纠错通过 `SET LOCAL credit.correct_history='on'` 按联合主键更新，主键、创建日期和创建人不可改。`updated_at` 不代替业务日期。已有 `retired_diff_fields` 保留历史证据。

`0018_credit_entries.sql` 逐字段迁移全部旧 diff 日期，机构资料取各字段最新值。只有原来明确撤销的记录转换为 `1970-01-01`，以后恢复获批的记录保留实际期限。迁移在同一事务核对全部历史业务字段和当前撤销名单，不一致则回滚。只有状态/元数据的旧行保留其业务日期和事件，用继承备注承载，未登记备注才初始化为空字符串。

生产切换先执行默认 `pnpm credit:db:migrate`，仅应用增量阶段。旧 Worker 的 diff 写入继续镜像，新 Worker 此时可以读长表，写入暂返回 503，机构改名暂时拒绝。确认新 Worker 接管全部流量后执行 `pnpm credit:db:migrate -- --finalize` 应用 `0019`，同一写锁等待旧事务完成，再关闭旧函数、将 diff 改名为只读 `legacy_diff` 并开放 entry 写入。默认命令不会提前执行收尾。ledger 已完成 `0019` 后，默认命令继续执行后续 migration。`0020` 新增定稿字段，历史记录保持 false。旧资料不再参与运行时查询，不把旧 Worker 直接回滚到已收尾数据库。

已写撤销哨兵的机构重新获批必须登记真实的新到期日。过渡期旧入口只改审批状态、没有可恢复期限时明确回滚，不允许保存成功却继续显示撤销。原来一直没有到期日的未撤销机构仍按底层 status 处理。

## 已用额度

金额以 PostgreSQL `numeric` 存储，查询汇总与元转亿元不转 `float8`。授信报表、详情联动和导入残差共用十进制金额运算。派生金额与二级余额按六位小数、半入舍入归一。融资原始一级存续额保留元金额分级精度，仅在现有数字 DTO 边界转换为 number。该 DTO 不保证数据库 numeric 全取值范围的无损字符串传输。

- 可用额度为 `available = total - used`。使用率为 `utilization_pct = used / total * 100`。
- `total=0` 时使用率必须为 `null`，页面显示缺失，不显示 0%。
- 当前单机构派生已遵循零分母规则，汇总 `build-report.ts` 仍返回 0。汇总是已知实现偏差，待业务修复，不改变上述口径。


`institution_client` 保留静态一对多客户关联，归属规则见 [客户与授信关联](clients.md)。

- 收益凭证、同业拆借按截面日期调用 `financing.credit_usage_as_of(date)` 读取存续本金，元转亿元。不在 entry 中重复存一份融资已用值。
- 债券投资按静态客户关联读取 `financing.bond_investors` 的实际投资人，由 `credit.bond_primary_usage_as_of(date)` 汇总已起息且未到期、结清或关闭的一级发行认购金额（元）。到期当日不计存续，不按当前债券状态回写历史。债券投资已用＝一级发行存续额（亿元）＋登记的二级买卖净余额（亿元）。正余额代表净买入、负余额代表净卖出，后续按业务日登记累计净余额。
- 总已用为五项有效值之和。客户未关联时，融资已用、总已用及可用保持缺失，不能当零处理。人工使用额及二级买卖净余额的空值沿用合计时按零处理的口径。
- `status` 保留底层审批事实。视图先识别 `expiry_date=1970-01-01` 为已撤销。有到期日时，报告日不晚于到期日为已获批，否则为申请中。无到期日沿用底层 status。起始日只展示，不参与状态覆盖，不回退上一期限。
- 一览表、汇总、周报、近期批复、日历、风险、周比较与图表统一排除所选日已撤销主体。原始管理查询仍能读其 entry，撤销前的历史截面不受后续哨兵影响。有效总额、已用/可用和使用率只统计所选日已获批机构。到期不会改写底层 status。
- 原 Excel 融资分项值仅在导入时与融资台账比较并输出警告。不再存 `importedTotalUsed` / `importedUsedAmount`。核对脚本输出当前派生额和缺失关联，原始报表差额在导入阶段核对。

## 接口与维护

- AI 授信查询只使用 `GET /api/credit?view=masked&date=YYYY-MM-DD&institutionId=数字ID`，日期默认上海今天，ID 可省略。沿用 `credit.institution:read` 与 `no-store`。响应为 `reportDate`、`amountUnit=亿元`、`institutions`，机构仅使用字符串 `institution_id`；金额为十进制字符串，缺失为 `null`。不支持机构名称、日历或自由查询参数。
- `0023_credit_masked.sql` 将脱敏视图统一命名为 `credit.masked`（上海当日）与 `credit.masked_as_of(date)`（历史截面）。直接从 entry 白名单取最新字段，融资用量按 `institution_client.institution_id` 汇总，不查询 `credit.institution` 或 `public.client`。保留额度、已用、剩余、使用率、期限、状态及报告日定稿标记；不返回机构资料、客户资料、自由文本或作者。日期继承、撤销排除、融资存续、缺关联和零分母与一览表口径一致。历史台账债券已用不进入投影。旧视图与函数直接改名，不保留别名。
- MCP 的 `credit_report` 固定读取上述脱敏模式；新增/修改授信工具退出 AI 目录，网站维护接口继续按原权限使用。不提供独立授信 skill 或专用登录 CLI。

- 后端直接查询当前/对比 SQL 截面、客户关联、用量、申请事实及所需事件日期的截面，显式投影业务字段，不返回内部作者或审计 ID。当前/对比日期保留完整余额，其余日期仅返回相关机构用量。提前续作的旧有效期限从 SQL 历史事实读取。不在 Worker 构造机构展示对象或拼装报表。
- `GET /api/credit?date=YYYY-MM-DD&month=YYYY-MM` 返回 `CreditDataset` 原始业务数据与日期上下文。浏览器共用 `buildCreditReport(data)` 生成一览表、总额、使用率、周报与日历。后端 GET/PATCH 不调用该函数。CLI/Excel 核对适配器复用同一纯函数，不保留第二套公式。`month` 默认所选日期所在月。非法日期/月为 400，早于历史覆盖起点或无记录为 404，连接异常为 503。
- 周环比优先采用七天前的截面。历史不足七天时取更早的最近变更日。周报申请事件由 `entry.event` 决定，续期与扩额同日归为扩额。本周内续期的机构不再列到期。到期日期从当前期限生成，旧期限被续期覆盖后不再提醒。首次历史导入作为基准，不虚构当日新增批复。
- `PATCH /api/credit` 以 `operation`、`reportDate`、`institutionName` 和 `changes` 写入申请，`changes` 仅传修改字段。`viewDate` / `calendarMonth` 指定当前页面上下文，省略时沿用业务日及其月份。普通响应 `scope=institution`，只返回目标机构的原始数据替换集。空数组可删除已失效的数据。

  浏览器替换该机构的数据并响应式重算报表，保留筛选、排序、详情弹窗及日历月份，无额外 GET。历史起点或比较期变化时 `scope=context` 补齐事件及比较截面，当前日仍只返回目标机构。前端保留其他机构的当前截面，重算受影响部分。保存途中切换日期/月时，通过上下文和请求序号拒绝旧响应。

  维护操作不能变更总授信额度；后端在写锁内按业务日截面及数据库六位金额精度核对，拒绝增加、减少、清零或首次登记总额，同值与省略总额可提交，分项额度仍可维护。续期、扩额、撤销、字段白名单、期限约束、事务及审计继续由后端验证。前端派生值不作为写入依据。用户 ID 来自 `locals.user.auth0Id`。
- `POST /api/credit` 使用相同结构新增机构，至少包含机构性质、状态、保密协议状态。主体重复返回 409。成功后可继续维护全部详情。
- `GET /api/credit?view=usage&date=YYYY-MM-DD&institution=主体&type=bond_investment|yield_certificate|interbank_lending&offset=0` 仅返回该主体、该日、该品种的存续融资条目及合计，沿用授信读取权限。每页100条，offset最大100000。未关联时合计缺失；有关联且无存续条目时为0。债券每行展示关联客户实际认购额，同一债券可有多个客户条目。非法view、日期、主体、品种或分页参数返回400。
- 一级发行存续额、收益凭证、拆借原始用量由服务器提供。浏览器派生债券分项及总已用。债券 `secondaryUsedAmount` 可编辑。禁止通过 `usedAmount` 覆盖派生债券合计。

  所有写入校验同源、身份与 `credit.institution:update` 权限。GET 使用 `credit.institution:read`。所有响应 `Cache-Control: no-store`。
- 已登记金额传 NULL 不能清零，API 返回400并提示填0，避免页面清空后误报保存成功。尚未登记的金额仍允许缺失。导入空白不覆盖原值，若四项额度继续继承非零值，返回逐机构警告。dry-run明确提示空白与零的区别。

## 导入

Excel 暂时保留本地导入，浏览器不解析、不上传源文件。

```sh
pnpm credit:import -- --file /absolute/path/授信周报.xlsx --date YYYY-MM-DD --dry-run
pnpm credit:import -- --file /absolute/path/授信周报.xlsx --date YYYY-MM-DD --user-id 'auth0|已核实的用户ID'
```

dry-run 核对模板、机构数、一览表/周报口径与工作簿总额差异。实际导入返回 `addedDiffCount`，先建立主体和静态关联，再以原表债券真实值减去当日线上一级存续额登记二级买卖。金额比较与写入在同一事务完成。非零债券真实值缺少客户关联时整次导入回滚。

缺席机构不会被自动删除或撤销，撤销需明确状态。来源报表不会覆盖已存在的静态客户关联。先验证目标连接，再写入。不要将源文件提交 Git。

## 页面与日历

四个侧栏入口为授信总览（`/credit-workbench`）、一览表（`/credit-workbench/ledger`）、日历、周报，继续复用 `WorkbenchShell` 与 `CreditView.svelte`，保留机构排序、筛选和周报版式。原授信助手兼容地址重定向到门户并打开全站 AI 侧栏。公开材料查询由侧栏使用 MCP 检索工具。申请弹窗只办理新增、续期、扩额、撤销。机构详情由授信管理员编辑并显式保存为维护事件。

- 顶栏“报告日”使用左侧日历和右侧季度快捷选项（如26Q3）选择任意截面。“授信申请”办理申请事件。详情维护固定使用顶栏全局报告日，不再单独选择记录日期。授信申请业务日默认报告日，仍允许另外选择业务日。

  维护详情的授信总额只读；总额变更通过授信申请办理。四项额度、法透/其它人工已用和债券二级买卖净余额可编辑，债券投资已用和可用也可编辑，分别以已用减一级发行、额度减可用减一级发行反算二级买卖。其余金额随输入即时计算。一级发行、收益凭证已用与拆借已用为明细按钮，可查看存续融资条目；具备融资数据读取权限时条目链接进入融资负债详情。明细返回保留未保存字段，弹窗隐藏滚动条但保留滚动和键盘操作。债券合计已用与可用的反算联动保持不变。所有详情修改与联动计算均按全局报告日保存。

  无维护权限时字段不可交互且保持相同颜色。`credit` 角色授予 `credit.institution:read`、`credit.institution:update`。Gateway 写接口按权限拦截。
- 总览页内标签为“仪表盘”和“银行授信情况”，通过 `?tab=bank-credit` 直达银行表格，默认仪表盘。标签链接保留报告日；切换复用当前数据。银行表按报告日已获批机构展示政策性、国有、股份制、城/农商行及其它（外资、境外、民营）五类，未知性质独立保留。展示授信/已用/剩余额度及合计，金额以亿元保留两位小数；任一参与机构额度或已用缺失时对应合计保持缺失。剩余为额度减已用。前十大按总授信额度降序、同额按机构名排序，缺失总额不排名，不合并独立授信主体。
- 总览快照后按银行类型、授信品种、Top10 三行排列，每行依次为额度、已用、使用率；随后为授信状态、到期期限直方图、授信额度使用率及预警。金额与使用率仅统计报告日已获批机构，状态家数包含申请中机构，统一排除撤销。银行类型汇总任一主体额度或已用缺失时保持缺失。品种额度汇总非空的已登记额度，全未登记为缺失，明确登记0仍为0；品种使用率的分子和分母严格采用该品种已登记额度的同一主体集合，其中已用缺失或额度合计为0时使用率缺失。品种已用展示债券投资、收益凭证、法透、同业拆借四项，汇总全部有效主体，融资用量缺失时保持缺失，法透人工空用量沿用报表合计时按零处理。九宫格标题统一为“授信额度/已用额度/使用率（按类型/按品种）”及“授信额度/已用额度/使用率 Top10”，不显示已登记标记；tooltip显示各品种已登记/未登记家数、使用率同范围额度与已用，以及未登记额度主体的非零已用。品种额度互相独立，不合成总授信额度；其它没有独立额度和使用率。Top10 分别按各自指标降序，缺失不参与排名。到期直方图沿用期限分组，无到期日独立列组。后置授信额度使用率仪表盘采用全部有效主体完整额度与已用合计，缺失或零分母显示缺失；使用率与预警直接从当前 `buildCreditReport` 截面派生，不使用演示数据，不显示阈值说明文案。单序列图表与只有一个有效类别的状态图不显示图例。
- 一览表不显示序号，机构性质位于最左，按显示分类合并居中并使用稳定浅底色。国有银行/国有行、境外行及外资行/外资行共用显示分类，原始机构资料不变。先筛选再分组，性质排序控制组序，其余排序键在组内保留优先级。
- 一览表“导出Excel”由浏览器生成单 sheet 工作簿，沿用2026年9月30日授信一览表的双层表头、机构性质合并、列宽、宋体、边框、金额与日期格式和 M4 冻结位置。导出点击时所选报告日全部未撤销机构（含申请中），采用默认分类及额度排序，不受搜索、风险筛选或临时排序影响。汇总只统计有效获批机构，总额及已用/剩余共用报告金额字段，任一有效机构缺失时对应合计留空；融资分项缺失保留空白，人工已用合计沿用空值按零口径。仅输出数值，不写公式或条件格式。退休两融及旧说明占位列隐藏且数据留空，不恢复旧业务数据。文件名含报告日，源模板不随应用分发。
