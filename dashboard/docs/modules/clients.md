# 客户与授信关联

`public.client(id, name, fullname, type, subtype)` 保存共享客户身份，`name` 是唯一业务简称，全名可空。汇总客户、自然人和只有简称的机构不补造法律全名。一级分类为银行、理财子、券商、基金、营业部客户、其它。

银行性质和券商自营/资管放 `subtype`。银行资管另建“银行简称+资管”客户（`type=理财子`、`subtype=银行资管`），不复用母行法律全名。未标注资管的银行客户归银行自营。

## 负债关联规则

- `financing.debt.client_id` 每笔最多关联一个客户，各继承子表分别装外键、索引和触发器。`counterparty` 保留业务原文，不覆盖。
- 初始回填只更新空关联，手工指定的客户优先。修改交易对手时重新识别，改其他字段不影响人工关联。
- 2021-09-06 的 5 亿元集团借款（2021-09-14 到期）已人工纠正为集团公司，导入转换执行同一精确规则，防止旧工作簿重复建账。
- `public.client_alias(alias, client_id)` 只存精确的特殊映射，`alias` 是 `public.client_match_key` 生成的标准化键。实际投资人例外优先于通用规则。
- 通用规则按 `client.name/fullname` 识别：统一全半角、空白、引号、来源前缀、公司后缀，以及“农村商业银行/农商银行→农商行”。银行名称允许唯一且省份不冲突的省份简称及“银行/行”变体。同名跨省或多个候选保持空关联，吸收合并备注不改变客户身份。
- 明确的“资管/资管部/资产管理/资产管理部”后缀（含括号）归独立资管客户，金市/自营及无标识归银行。资管客户未维护时保持空关联并提示维护，不回退到银行主体。
- 具名资管/信托/私募产品只匹配已建档的完整产品名，且前文为公司账户及可选的“代/代表”。理财产品按已知理财子的名称前缀识别，同时出现两个理财子名称时须有精确例外。管理人名称中的“资产管理”不构成资管标记，未知产品不猜测投资人。
- 删减别名时，同一事务重新识别全部负债名称、授信名称、客户简称/全名和旧精确别名。任何归属变化都回滚。

## 借入资金汇总表导入

新增负债先按交易对手识别。未命中时，在导入事务内按来源名称自动建档并关联，营业部大客户归“营业部客户”。

- 客户名称取来源明确的主体或具名产品，未核实的法律全名保持空。建档与负债写入同一事务。
- 名称有歧义或无法安全提取时负债仍导入，空关联和待核对名称在结果中提示，不覆盖既有人工关联。
- 原始负债无交易对手时不建虚拟投资人。

## 授信关联

- `credit.institution_client` 是唯一的静态一对多关联表，不存报告日。每个客户只归属一个授信主体，由唯一约束防止重复计入。上海农商行（金市）关联上海农商行，上海农商行（资管）关联上海农商行资管，其它银行同理。
- 银行与理财子分别建客户，即使授信合并也不合并客户法人。营业部客户和具名投资产品可以有客户关联但无银行授信，这是正常的范围差异。
- 新增授信优先用已有静态关联。没有关联时，仅当完整名称或 `&` 合并名称全部精确识别且不与既有归属冲突才自动关联。重导任意业务日期都保留静态关联，改关联即影响所有日期的融资额度归属。
- 省联社成员按人工确认清单逐一维护，运行时不按省份字符串自动扩大范围。
- `financing.credit_usage_as_of(date)` 读取截面日仍存续的收益凭证和同业拆借本金（元），授信 repository 按静态关联汇总并转亿元，未关联为 NULL。债券一级发行经实际投资人 `bond_investors.investor_id` 使用同一归属。全部融资品种统一按客户身份汇总，银行与资管不能互相代入。
- 授信存储、按日截面和已用额度公式见 [授信工作台](credit-workbench.md)。

## 初始化与维护

先运行融资 migration（含公共客户主表和负债外键），再运行授信 migration，生产不执行临时 DDL。

```sh
pnpm financing:db:init -- --schema-only
pnpm credit:db:migrate
node scripts/maintain-clients.mjs /absolute/path/client-manifest.json
node scripts/maintain-clients.mjs /absolute/path/client-manifest.json --apply
node scripts/reconcile-client-usage.mjs /absolute/path/reconciliation.json
```

- 清单字段：`clients` 为上述主表字段（不传 id），`aliases` 为 `alias/clientName`，`creditMappings` 为 `institutionName/clientName/notes`。
- 默认事务回滚预览，`--apply` 才保存。清单和台账核对结果放在未跟踪的运行目录。
- 清单按名称更新客户、别名和静态归属，不删除未提及的客户、别名或关联。已能由通用规则识别的别名不重复写入，把旧例外改回通用规则的归属时删除该例外。含 `matchKind` / `notes` 的旧别名字段会被拒绝。
- 改变归属须显式维护 `institution_client`，同一客户关联多个授信主体会被数据库拒绝。
- `reconcile-client-usage.mjs` 输出各历史变更日的派生额和缺失关联。
- 修改历史金额、日期、现金流后，按需显式刷新既有月度衍生指标。

## 融资客户名单

`/financing/clients` 提供按名称/全称/类型/别名搜索、分页、新建与编辑，沿用 `financing.data:read/create/update`，Gateway 登记页面和 named actions。前端只提交客户白名单字段。公共客户表不向通用数据后台开放，数据库访问方式见 [融资数据](financing-data.md#数据访问与-rls)。

专用客户服务在事务内维护主表和精确别名，用融资/授信维护锁、版本校验、唯一约束和归属检查。

- 改名保留旧名称为别名。与已有客户冲突或改变已知来源归属则回滚。
- 保存后只回填尚未关联的负债，不覆盖人工指定。
- 不提供删除客户入口。
