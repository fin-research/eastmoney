# UI/UX 设计规范

本文件是 Dashboard 全部页面的唯一 UI/UX 规范。新增或修改页面时优先复用既有组件与令牌，不在业务组件中另建平行样式体系。

## 视觉基础

- 采用清晰、克制的机构级研究终端风格：白色工作区、冷灰顶栏与深色侧栏、白色卡片、轻边框、低阴影和适度圆角。
- 门户保留已确认的暖白背景与彩色入口卡片。业务工作台通过导航图标、分区标题和状态色增加层次，沿用现有亮色体系，不改成单一灰色界面。
- 页面背景 `#f6f8fb`，主文字 `#172033`，次文字不浅于 `#667085`，品牌蓝 `#2f6fd6`。
- 全站只使用系统无衬线字体栈。数字仅使用 `font-variant-numeric: tabular-nums` 对齐，不得为表格或数字切换另一套字体。
- 正文与关键辅助信息保持可读。常规文字不低于 `0.875rem`，图表坐标、图例和报告正文原则上不低于 `1rem`。
- 普通工作台采用 Maia 的圆角组件（卡片 `16px`、胶囊按钮与输入框）。定稿报告保留 `6px / 8px / 10px` 令牌。主操作、输入框和图标按钮的触控尺寸不小于 `44×44px`。

## 字号与字重

- 根字号固定为 `16px`，业务组件使用 `rem` 表达字号，遵循 `0.75rem / 0.8125rem / 0.875rem / 1rem / 1.125rem / 1.25rem / 1.5rem` 的统一层级，不新增无依据的任意字号。
- `0.75rem` 与 `0.8125rem` 仅用于日期元数据、日历状态和紧凑表格，`0.875rem` 用于低优先级标签。正文、图例、图表坐标及指标卡第三行辅助信息使用 `1rem`。模块标题从 `1.125rem` 起，页面标题从 `1.25rem` 起。
- CSS 的 `font-weight` 和图表配置的 `fontWeight` 只使用 `normal`、`bold`、`bolder`、`lighter` 等语义关键字，不写 `650`、`700`、`750`、`800` 等数值字重。
- `normal` 用于正文和辅助说明，`bold` 用于标签、表头与模块标题，`bolder` 仅用于页面标题或指标卡主值。不得用字重替代字号层级。
- 指标卡固定为左侧语义图标、右侧名称/主值/第三行辅助信息。第三行使用卡片语义色，有符号变动数字再按涨跌方向覆盖颜色。授信周报的第三行使用标准正文色，省略比较前缀，无变动显示“持平”。

## 页面层级与共享布局

- 一级称“板块/工作台”，对应门户入口。二级称“页面”，对应左侧导航。三级称“标签页”，只位于 header。各级都必须有真实链接，支持直接打开、刷新和浏览器前进后退。
- 工作台统一使用 `WorkbenchShell`，所有业务 header 复用 `src/lib/workbench/PageHeader.svelte`。一级与二级标题使用同一系统字体、`1.25rem`、`bolder`、`--text-1`。品牌行使用 `0.875rem`，桌面顶栏基准高度为 `64px`，内容换行时自然增高。禁止普通页、报告页或业务样式另行覆盖标题。
- `PageHeader` 的 `section/current` 提供层级链接，`tabs` 提供标签页链接。只有两个及以上标签页才显示标签栏。顶栏为白色、工作区为淡冷灰 `#f6f8fb`、侧栏为深灰 `#202a38`。共享外壳只以品牌蓝 `#2f6fd6` 作为强调色。

  选中标签使用品牌蓝文字和底线，悬浮标签使用淡冷灰底。标签栏贴合顶栏底边，不留白缝，也不使用向工作区延伸的装饰圆角。窄屏标签栏独占一行、局部横向滚动。单面页面不补造“总览”等占位标签。
- 通知管理使用 `/management/messenger?tab=delivery` 与 `?tab=test`。无效或默认 tab 回到消息投递。市场点评沿用 `/market-briefing` 与 `/market-briefing/text`，标签链接保留报告日期。弹窗选项、表格筛选和年月切换仍属于局部控件。
- 旧 `/bond`、`/secondary-bond-pool`、`/financing-model` 入口使用同一工作台装配，保留 URL 与查询参数。报告正文、图表和打印尺寸沿用原有组件。资金日报归档 HTML 原样返回，不注入应用布局。

## 内容与层级

- 标题区域只呈现标题与导航，不放业务操作按钮。操作放在独立工具栏或内容底部操作区。

- 所有页面禁止解释性小字、口径扩写和功能提示，包括标题下说明、缓存策略及系统实现说明。不得移入 tooltip、占位符等位置。指标口径变化不扩写标签，例如保持“已质押”，不改为“已质押持仓市值”。交互说明只通过控件、状态和布局表达。保留必要字段、业务数据、错误反馈及可访问名称。
- 指标卡只保留名称、主值和有决策意义的变动。下方优先展示“较上周/昨日/月末”的变化量，变化数字必须按方向着色。禁止“已核对”“参与统计”等状态废话。
- 指标卡图标、图标颜色和卡片浅色底必须与指标语义一致，同一组卡片避免重复颜色。
- 除市场点评页面外，模块标题不得添加 `01`、`02` 等序号。
- 空状态、错误和加载文案应直接说明状态与下一步，不添加装饰性描述。

## 色彩与图表

- 涨跌颜色服从用户配置：默认红涨绿跌，也支持绿涨红跌。颜色之外必须保留正负号、方向文字或图形差异。
- 业务状态色保持独立语义，例如成功用绿色、危险操作用红色、主操作用蓝色，不随行情颜色配置互换。
- 柱状图、饼图和分类图必须使用与 `fin-ops` 一致的多色序列：`#2f6fed`、`#16a394`、`#6941c6`、`#f79009`、`#d92d20`、`#0ba5ec`、`#6172f3`、`#12b76a`。
- 图表必须提供图例、tooltip 和 ARIA 描述。不得只用颜色区分类别。tooltip 限制在图表内并允许长名称换行。
- 面积、柱、线、点等图形应服务于数据含义，不使用无业务含义的渐变或装饰动画。主要动画不超过 `300ms`，并尊重 `prefers-reduced-motion`。
- 图表容器必须有稳定高度并随容器尺寸重绘，避免标签裁切、重叠和无效留白。
- 业务数据图表必须经统一 `ChartHost` 用 ECharts 绘制。禁止用手写 SVG、Canvas、CSS 宽度条或 DOM 图形模拟柱、线、饼、仪表、曲线等数据图表。SVG 只用于图标和无数据含义的装饰插图。
- 同类型图表必须复用 `src/charts/` 中的配置构造与样式：统一配色序列、字号、网格、轴线、图例、tooltip、ARIA、动画时长和 `ResizeObserver` 重绘机制。页面组件只传入业务数据和可访问描述，不得内联一套 ECharts option。
- 横向比较图统一使用圆角横向柱和右侧数值标签。一般品种比较可使用浅色背景轨道，正负因子贡献图保持透明底且不显示网格线或背景轨道。趋势与期限曲线统一使用相同轴线、虚线网格、线宽和 tooltip。业务阈值通过 ECharts `markLine` 表达，不手写绝对定位线。

## 布局与组件

- 桌面端内容最大宽度 `2100px` 并居中。同一行卡片上下边线对齐，表格和图表在模块内部处理溢出。
- 移动端保持既有模块 DOM 顺序，按单列自然排列。不得用折叠、分页或重排破坏阅读顺序。
- 表格表头清晰、行高一致、数值右对齐、名称左对齐。移动端使用表格区域局部横向滚动，不让整页横向溢出。
- 弹窗必须在视口内居中并限制最大高度，超出内容仅在弹窗内部滚动。危险操作必须二次确认。
- 可用按钮及按钮式链接、控件统一显示鼠标手形；禁用控件不显示手形，共享按钮的禁用链接阻止鼠标交互。悬浮反馈沿用各组件变体，不统一覆盖业务底色。
- 原生表单必须有可访问名称。图标按钮必须有 `aria-label`，键盘焦点必须清晰可见。
- 指标卡、面板、模块标题、状态标签、表格控制和图表容器必须优先复用已有共享组件与样式类。同一信息结构不得在不同标签页创建平行组件。确需变体时以 props、modifier class 或共享图表 renderer 扩展。
- 工作台各标签页使用同一套页面内边距、卡片边框、圆角、阴影、标题和表格规则。工作台令牌必须映射全局设计令牌，不维护独立的品牌色、背景色、正文色或圆角体系。

### 共享组件归属与复用顺序

- 复用决策固定为：先搜索现有组件和样式。能直接使用则直接使用。信息结构相同但有轻微差异时扩展 props 或 modifier。只有确认没有可复用基础后才允许新增共享组件。禁止先在页面内实现，再以“后续统一”为由保留平行版本。
- 普通业务模块卡片默认使用 `src/components/ModuleCard.svelte`，兼容工作台 `.tr-panel`。组件统一维护白色表面、轻边框、工作台 `16px` / 报告 `10px` 圆角、低阴影和内边距。总览、交易管理、授信管理、研究辅助、流程中心、二级池和融资择时模型的普通模块必须直接复用该组件。页面只负责网格和确有业务含义的内容布局，不得重复声明卡片表面、边框、圆角或阴影。市场点评现有高密度报告面板可保留专用结构，但必须映射同一组全局令牌，不得建立第二套视觉参数。
- `src/components/MetricCard.svelte` 是市场点评、交易研究工作台普通快照指标、二级池和融资择时模型的唯一指标卡基础。名称、主值、单位、第三行变动、圆形图标容器、图标线宽、语义色、浅色卡片底、边框、圆角、阴影和文字换行均由该组件负责。业务页只配置 `tone`、`iconPosition`、`compact` 与业务数据。不得再定义页面级 `.core-card`、`.metric-card`、`.ledger-metric` 或同义结构。研究辅助经济数据矩阵每卡含日期和 ECharts 趋势图，统一用专用 `EconomicIndicatorCard.svelte`。该组件不替代普通指标卡。
- `src/lib/trading-research/SectionHeading.svelte`、`PanelHeading.svelte` 和 `Badge.svelte` 分别负责工作台模块标题、卡片小标题和状态标签。所有工作台标签页及融资择时模型必须复用它们。`PanelHeading` 统一使用左侧品牌色短线、`1.125rem` 粗体标题和下方控件行，筛选框在桌面端保持一字排开，不复制标题 DOM。
- 市场点评的高密度内容面板继续复用 `.dashboard-panel` 与 `.panel-heading` 并映射全局卡片令牌。二级池及其余工作台内容面板统一复用 `ModuleCard.svelte`，不得仅因标签页不同而改变边框、圆角、阴影和标题层级。
- 市场点评桌面鼠标操作区采用 `32px` 控件，避免 `44px` 通用按钮撑高标题。通过 `.page-shell` 的 `--report-control-size` 统一顶部切换、按钮、日期、聚焦 AI 生成和文字版工具栏尺寸。`900px` 以下或具有粗指针的触屏设备恢复 `44px`。此为高密度报告的尺寸例外，其他页面继续沿用通用触控尺寸。
- `src/components/ChartHost.svelte` 负责图表生命周期、容器尺寸与可访问名称，`src/charts/` 负责同类图表 option。业务模块不得另建图表容器或内联独立视觉配置。
- 共享组件样式由组件自身或其唯一共享样式文件维护。业务页 CSS 仅负责网格、模块位置和确有业务含义的布局变体。不得覆盖共享组件的字号、颜色、边框、圆角或阴影来制造局部版本。

### 业务工作台精修与报告隔离

- 所有工作台的 Header 与侧边导航共用一套外观，普通页和报告页一致。交易、授信、融资、管理导航统一使用深灰底、蓝灰选中底色、品牌蓝短竖线、白色选中标签、12px 圆角、48px 行高与相同线性图标。不按业务切换导航颜色。侧栏样式由 `workbench.css` 唯一维护，工作台内容圆角与控件规则只作用于 `.tr-workspace`，报告控件规则不得覆盖共享 Header。分区标题和指标仍通过既有组件配置业务语义色。
- `layoutReport`、`integrated` 和 `visualVariant="report"` 视图不启用业务工作台精修。授信周报显式使用 `visualVariant="report"`。市场点评、资金日报、负债周报、二级池周报及融资择时报告继续使用其既有版式。普通页面改造不得通过修改全局主题或共享卡片基础样式影响定稿报告。
- 顶栏依照实际内容换行，工作台名称与当前页面采用同一标题样式并提供层级链接。窄屏保留个人入口和业务操作。关闭的移动导航不可获得键盘焦点。固定新增按钮所在页面预留底部空间。
- 普通指标网格使用内容可承受的内在最小宽度，不能把三张窄卡硬塞入手机或窄面板。金额和单位分别传入 `MetricCard`。数据维护字段同样区分主值、单位和缺失状态，不能把缺失值当成零。
- 输入值使用正常字重，标签保留强调。按钮、输入框的颜色和边框由 shadcn-svelte Maia 基础组件负责。禁止旧页面 CSS 覆盖主按钮为白底白字。提问框作为组合控件使用一个外框和一个完整的聚焦指示，内部 textarea 不再重复画边框。
- 普通融资表格使用内容驱动列宽，日期完整显示，必要时在可聚焦的表格区域内横向滚动。版式报告继续执行其原有完整换行、无滚动条规则。
- 融资仪表盘的待办统一保留在顶栏提醒面板，日历占满一行。周末切换在日历标题控件区明确显示。发行试算只呈现已实现的额度校验，不展示 TODO 或后台接入占位卡片。
- 市场热点使用浅色画布、多色词云和白色详情面板。保留热度、证据与生成范围，正文完整展示。控件、标签、字体和圆角映射全站令牌，移除暗色专用字体及发光效果。细则见 [热点视图约定](design-system/eastmoney-market-hotspots/MASTER.md)。

## 门户与工作台响应式

- 页面级全局 `html/body` 背景、最小宽度或滚动锁不得写在路由组件的常驻全局样式中。全屏页面应由自身根容器承载背景与溢出，避免客户端导航后污染其他页面。
- 交易研究工作台使用可深链的 path 页面：`/trading-research` 为总览，其余模块使用 `/trading-research/<module>`，包含市场热点和政策跟踪。首页只保留交易研究工作台入口，不再单独展示这两个模块。不得使用 `?view=` 保存二级页面状态。
- 交易研究工作台使用 App 型框架，全宽顶栏位于侧栏与内容区上方。桌面用 `PanelLeft` / `Sidebar` 线性图标折叠侧栏，移动端用菜单图标打开抽屉。侧栏不放独立 `tr-brand`。顶栏不放单独的门户返回按钮，点击“东方财富证券 · 资金管理部”返回研究门户。
- 交易研究工作台路由存续期间，`html/body` 锁定为视口高度且不滚动。App Shell 也不得产生页面级滚动。唯一纵向业务滚动容器为 `.tr-workspace`，顶栏和侧栏始终留在视口内。顶栏当前位置统一用“交易研究工作台 / 当前模块”的语义化层级导航表示，“东方财富证券 · 资金管理部”作为其上方紧凑门户入口。
- 授信周报、二级债券池运营周报和融资择时模型报告统一视为版式报告：屏幕报告区最大宽度为 `1080px`。打印只输出报告区，使用 A4 portrait、零页边距和 `210mm / 1080px` 的固定 `zoom`，并显式恢复桌面栅格。禁止因打印视口变窄触发响应式重排。工作台的 `#tr-workbench-main` 必须直接使用语义化 `<main>` 并作为二级池、融资择时报告画布，报告组件不得再增加仅用于套宽度或背景的 shell/report 包装层。独立路由只保留一个报告主容器。负债周报在本仓库融资模块中使用同一打印基线，其中六张固定 A4 页面可保留必要的分页 DOM。
- 版式报告内所有表格使用内容驱动的自适应列宽，不设置固定或最小表宽。表头、名称、说明和长文本必须完整换行，表格及其容器不得出现水平或垂直滚动条，也不得溢出报告区。
- 写入、上传、删除、导出和后台刷新产生的系统反馈统一发布到全局消息层。按钮可保留进行中状态，页面内不得再设置 `ledger-status`、`status-region` 等消息占位区。加载、空数据和整页读取失败仍属于内容状态，不视为系统通知。
- 工作台只呈现业务模块、数据基准日和业务状态。演示边界、静态数据来源、未来数据库或 `/data/*` 接入方案仅写入工程文档，不在 UI 添加提示条、状态胶囊、页脚免责声明或小型上下文 header。
- 使用 `portal` 的页面必须保留位置稳定的组件根节点，只移动根节点内的操作区。不得把组件的首个根节点移到外部后，留下其他根节点参与 Svelte 片段卸载。授信助手的实际组件挂载、视图切换、卸载和迟到响应均由 DOM 回归测试覆盖。
- 根 layout 在所有页面右下角固定显示紧凑 AI 标签。打开后桌面 AI 侧栏占据布局宽度并压缩当前页面，移动端占满视口。侧栏包含通用对话和业务任务两个标签。对话支持本机按用户隔离的会话历史、新对话、工具选择、Ask/Act 模式、写操作确认、流式正文、停止与复制。

  任务发起后自动进入详情，在固定位置逐条替换模型公开 summary。完整记录通过折叠区展开，终态结果显示在其下方。完成后面板保持打开并发布全局完成通知。任务列表保留当前前端会话内的状态与结果。面板支持关闭、Escape、焦点恢复和减少动效。
- 保留的 CreditAgent HTTP/DO 会话采用一轮 AI Search 答复。`CreditActivityView` 只显示处理状态，模型 summary 进入统一 AI 面板。该兼容路径不再提供独立页面入口。

### 交易流程图

- 交易流程以用户提供的参考图为视觉验收基准，必须实际检查浏览器呈现。顶部品种分类不作为流程节点、不连线，保留浅色品种框，文字居中，折叠控件统一放右侧。询价位于各品种下方，先于共通交易要素。多个前序指向同一节点时，该共通节点自动居中。独立节点留在所属列，同名不合并。编辑面板显示所属流程和前序/后续节点，流程选项只有业务流程，不能包含“共通节点”。

  后续连接和上移/下移修改业务顺序，拖动只改位置。共通节点之间存在流程节点时不添加跨越直连。分支子节点向右展开，同级子节点以品种色浅边框归组，节点、连线和组框同步滑入淡入、收回淡出。主干从底部中心出线并从顶部中心入线，分支首条连线使用左右侧出口，主干继续向下。

  左侧时间轴全长着色，实时水平线位于节点下层。编辑模式放全局 header，删除内容小标题和整排操作控件，不使用缩放把全部节点压进一屏。
- 交易流程使用 Svelte Flow 的节点与连线表达业务关系，不使用普通模块卡片包裹品种或共通步骤。沿用全局令牌与系统字体，节点内不放编辑或拖动按钮。编辑面板只在编辑模式点击节点后显示。桌面三条流程的横文字标签吸附右侧，纵向排列。手机标签在画布顶部横排，点击展开或折叠。剩余流程重排填满工作区，展开/折叠用短动画并尊重减少动效。

  节点最大宽度 460px，列内居中，垂直间隔至少 76px。同一目标入边在同一水平线汇合。询价点击后展开无表头的可编辑表格，行底线右端的圆形加号在附近悬停或键盘聚焦时浮现。列名仅作 placeholder，并提供可访问名称。

  询价不参与完成状态。其余未完成节点白底，完成后加深品种色且保留原图标，分支须全部后代任务完成后着色。此类可编辑流程图不属于 ECharts 数值图表。

## 导出与验收

- 报告导出统一使用 3 倍像素密度 PNG，只包含报告正文，不包含操作工具栏、弹窗或临时状态。
- 导出期间不得改变用户当前滚动位置，导出完成后恢复页面状态。
- UI 改动先完成本地快速检查及相关测试。视觉变化须按 [TESTING](docs/TESTING.md) 本地审阅受影响页。合并队列执行完整构建及截图比较。

## 融资与管理模块复用

融资工作台和管理中心复用 `WorkbenchShell`。指标使用 `MetricCard`，模块容器使用 `ModuleCard`，标题使用 `PanelHeading`，图表通过 `ChartHost` 共用 registry，全站只挂载一个 `GlobalMessages`。融资页面的业务 CSS 限定 `.financing-scope` 并映射全局令牌，不再维护独立 Tailwind/shadcn-svelte 主题或全局 html/body 规则。六页负债周报保留专用报告版式。

融资待办使用顶栏“查看提醒”下拉面板，不占用正文高度。窄屏保留个人入口、提醒和周报操作，抽屉顶部跟随顶栏实际高度。项目和 SOP 详情在正文展示实体名称。含贴边表格或时间轴的模块使用 `ModuleCard padding="none"`。项目汇总类使用业务前缀，防止市场报告的网格规则泄漏到融资页面。

公共交互统一为可访问 label、44px 控件、保留失败输入、模态框内滚动、危险操作确认与减少动效支持。融资项目/SOP 普通字段共用 650ms 防抖串行保存。这属于模块行为，细则由对应模块文档维护。页面特殊布局、字段顺序和图表口径见 [模块分流](AGENTS.md#context-routing)。

## shadcn-svelte Maia 基础组件

- `components.json` 固定 `style: maia` 与 Lucide 图标库。`src/lib/components/ui/` 保存官方 Maia registry 生成的组件。品牌色与系统字体由 `app.css` 的语义令牌映射。不得重新引入旧 UI 框架或以平行 CSS 模拟基础组件。
- 基础按钮、输入框、选择器、复选框、标签、卡片与表格使用本地 shadcn 组件。变体使用 `tailwind-variants`，类名合并使用 `clsx` / `tailwind-merge`。图标使用 `@lucide/svelte`，定稿报告保留原有图标效果。交互使用 Svelte 5 Runes，动画使用 CSS / Svelte transition 并尊重减少动态效果设置。
- `--border` 是 shadcn 边框颜色，`--muted` 是次级表面。业务文本使用 `--text-muted`，业务线条使用 `--border-color` / `--line`。图表线条分别读取 `--chart-line-color` / `--chart-grid-color`，不得把控件令牌误当作图表颜色。
- 弹窗使用 `Modal.svelte` 封装的 Bits Dialog，保留取消拦截、内部滚动和关闭后焦点恢复。浮层、多选与页内选项卡使用 Bits Popover / Checkbox / Tabs。全站只挂载一处 `GlobalMessages` / Sonner，沿用消息去重与悬停暂停行为。
- 简单表单使用原生 SvelteKit named actions / enhance，复杂表单使用 Superforms 与共享 Zod schema。服务端加载和增量失效继续由 SvelteKit 负责，不引入平行状态缓存。数据维护保留 TanStack Table v9，图表继续复用 ECharts / ChartHost。
- `report-controls.css` 只覆盖 `.page-shell`、`.layout-report` 和非工作台 `.tr-shell` 下的控件。报告图表、模块、字号、间距及打印版式保持原截图。普通工作台的 Maia 样式不得扩散到定稿报告。
- 首页以与业务入口同级的卡片展示“管理”。共享 `AuthMenu` 只显示“用户图标 姓名 / 部门”，进入 `/management/me`。不再在各页增加管理图标或在融资顶栏另建角色/个人入口。部门读取已有资料，缺失时显示“未填写部门”。
- 共享姓名/部门入口在所有页头统一使用 `1rem`，排列在业务操作之后并靠最右。窄屏换行后仍右对齐。门户页头“资金管理部”标题使用 `1.25rem`。报告日期和版本选择器保留一个控件外框。
- 融资样式必须带完整业务子选择器。`tests/shadcn-contract.test.mjs` 检查技术栈与品牌色边界，DOM 与浏览器回归检查草稿、多选、弹窗和消息行为，不通过固定控件数量替代交互验证。

### 融资择时模型

- 首卡为整体结论，右上角显示当前票面模型的“尽快发行／等待”标签，债券品种与预测发行利率并列。结论正文始终直接可编辑，无编辑按钮。第二卡为 LCR、NSFR、资金缺口与主体利差业务指标，显示当期值与“历史P”。这些观察值不冒充模型输入。
- 因子贡献合在一张卡内，左为雷达图，右为当前 SHAP 正负条形图。桌面等宽并列，手机按雷达、条形顺序堆叠。未来发行窗口/模型验证仍采用3:1列，窄屏保持模块顺序单列。
- 页面不展示净节约和等待省钱概率。SHAP正值推高票面，负值降低票面，坐标单位bp，不做支持度反号。雷达图先合计各市场组的 SHAP 净贡献，再以净值绝对值表现强度，不恢复旧六维支持度或旧品种相对利差。
- 模型验证使用紧凑指标行，样本区间允许两行年月。图表、指标与容器继续复用ChartHost、MetricCard和ModuleCard。

### 管理个人入口更新

共享 AuthMenu 的已登录入口改为 `/management/me`“我的”，沿用管理 WorkbenchShell。个人资料不再使用独立页头。“我的 / 权限 / 通知”与管理员功能以一条导航分割线区分。无权限的页面入口和写控件不呈现。不以禁用按钮替代权限隐藏。通知设置使用既有 ModuleCard、Input、Checkbox、Button 和 PanelHeading。
