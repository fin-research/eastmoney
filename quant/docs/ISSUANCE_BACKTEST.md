# 统一真实票面回测

## 运行

```bash
uv run python main.py --issuance-backtest --as-of YYYY-MM-DD --input-snapshot outputs/inputs.json --backtest-output outputs/coupon-study
uv run python main.py --as-of YYYY-MM-DD --input-snapshot outputs/inputs.json --evaluation-dir outputs/coupon-study --forecast-output outputs/coupon
```

所有发行人、评级、期限、普通/次级、公募/私募共用一个模型，回测不按 `--issuer` 裁剪训练样本。输入日期必须匹配。日期纠错须保留来源并生成新快照，不能用事件覆盖文件改成绩。离线回放不触发 Choice。

## 默认三点研究

默认 CLI 运行 `model/short_coupon.py`：静态 Ridge、20 日报价 Ridge 和同配置 Huber，共用 T+1、T+14、T+30 三个自然日提前期。每笔发行总权重为 1，Ridge alpha 为 10，不搜索新算法。

- 票面日期索引采用三个国债的真实观测日，行业报价缺失保持 NaN，不删有国债输入的发行。利率研究仍要求原四列完整。
- 训练用 2026-01-01 前全部可靠成熟历史，`years=0` 表示全历史。训练期做年度扩展窗口 TSCV，每折至少 40 笔事件。插补、标准化和类别映射均在折内拟合。
- 2026 年各模型只拟合一次，训练截止固定为 2026-01-01，2026 年标签不进入训练和逐券票面历史。全市场每日加权融资成本和二级行情按严格早于预测起点的可用日期读取。
- 选择：序列 Ridge 的 TSCV 三点平均 MAE 须低于估值、静态及 Huber，且各点不差于 Huber。2026 年只报告验证，不参与选择。不合格时保留完整结果，不导出发布模型。
- 协议冻结输入、源码、环境、完整请求和未评分请求。逐折保存状态、预测、诊断和 receipt。加载时重算分母、指标和资格，拒绝旧的月度检查点。

`uv run python scripts/short_coupon_curve.py --snapshot INPUT.json --output OUTPUT` 运行同一固定协议。旧 PCA 及其他表示实验的参数已被拒绝。

## 指标

- 主要指标是提前 30 日 MAE，另报 7/14/60/90 日。同时披露 RMSE、实际减预测的平均偏差、固定双侧 ±5bp 命中率和不重复事件数。命中率不用于选模，sigma 仅作误差尺度诊断。没有真实发行的日期没有命中率。
- 现模型复现只覆盖其支持的不超过 30 日的提前期。共样本另报分母，不同样本的 MAE 不直接比较。
- 发行人留出时，同时移除训练标签和该主体的历史发行特征，仍可用当时公开的二级估值。样本稀疏的组须披露。
- 市场和历史发行特征严格早于预测起点，标签严格早于月初重训。调参起点和标签均早于评价开始。
- 已观察的历史都是研究数据，不称新的独立前向证据。AAA 行业曲线只是行业期限参考，不代表逐债池 B3 已完成。

## 冻结历史研究协议

```bash
uv run python main.py --issuance-backtest --study-protocol <协议JSON> --input-snapshot <冻结JSON> --backtest-output <实验目录>
```

输入日期来自协议，不传 `--as-of` 时也不读取当天日期。该分支不调用数据库或 Choice，不导出或发布线上包。协议字段包括 `schema_version`（1—9）、`stage`（`smoke` / `development` / `historical-report`）、`as_of`、`development_start`、`development_end`、`candidates`、`input_sha256`、`nodes_sha256` 和相对协议文件的 `nodes_path`。候选必须与 `model/issuance_study_protocol.py` 的版本注册表一致。

- `smoke` 只运行第一个有评价事件的完整月份。`development` 检查全部分母和门槛，无人合格则 selected 为空。
- `historical-report` 另需 `development_directory` 与 `selection_sha256`，只接受同一身份下通过开发门槛的冻结选择，不重选。
- 协议和月度 receipt 绑定输入、代码、候选及预测/训练诊断的哈希。不匹配时拒绝续跑，不自动重训或更新日期。新数据版本须显式登记，原协议与产物不覆写。
- 每个新研究轮次在查看上一轮结果后设计。历史区间只作描述，不消除跨轮搜索偏差。

| schema | 内容 |
| --- | --- |
| 1 | 原三组与原精确期限分组 |
| 2 | 九组经济基准残差对照 |
| 3 | 十组正则强度与稳健损失对照（Huber 截断阈值 10bp） |
| 4 | 四组行业相对发行溢价对照 |
| 5 | 公募限定，保留原 19 候选，分别登记条件均值与授权点预测选择 |
| 6、7 | 市场与发行溢价分离，见下节 |
| 8 | 训练窗行情平衡 |
| 9 | 目标期限动态与曲线形状 |

schema 2—4 按业务期限桶分组，对 B0 和 B2 同时执行保护门槛，两个控制组不参与升级选择。L1 / Huber 模型审计分别记录条件中位数 / 稳健中心，不能发布到预期节约字段。

### 择时代理审计

schema 2/3/4 每月另存 `.timing.csv`，哈希进入同一 receipt。预测起点固定，用当月模型的 0—30 日预测路径。按最低四分位规则决定立即或等待。评价器事后读取 AAA 行业期限曲线。它是二级市场代理：历史日期取已观察的报价工作日，最终发行条件事后给定。不称逐日真实票面或可交易回测。

缺整条代理路径的事件仍计入请求分母。`timing-report.json` 报告：

- 0/0.1/0.25bp 每日等待成本下的敏感性。
- 相对立即、约 7 日、截止日发行的收益，以及后悔成本、错误等待和尾部损失。
- 按月份和发行人聚类的描述性区间。

这些结果不用于事后改模型、等待成本或发布门槛。

### 市场与发行溢价分离（schema 6、7）

- schema 6 四组：原公募 Huber；定价日前行业曲线残差加零市场变化；同一残差加直接市场 Ridge；同一残差加训练窗去均值 Ridge。
- 市场层用日度行业曲线，在 1/3/5/7/10 年和 7/14/30/60/90 自然日期限上学习变化。月初只纳入完整到期的标签，Ridge alpha 为 1000、回看 5 年，中间期限线性插值，0 日变化为零。去均值只在训练窗按期限估计。
- 发行溢价标签 = 真实票面 − 定价前最后一个行业报价。预测 = 起点行业锚 + 市场变动 + 发行溢价，溢价模型不从提前天数或日历再学市场漂移。行业参考缺失的标签不进入该结构，生产缺起点行业曲线则拒绝预测。各候选在双端参考覆盖的共同事件上评价，保存 `reference-coverage.json`。
- schema 7 把市场层换成固定浅树（原始变化 / 训练窗去均值变化），参数见 `MARKET_TREE_PARAMS`。每个报价起点跨五个期限的权重合计为 1，不称五倍独立样本。
- 目标日前最后报价日就是当前已知报价日时，市场变化已知为零（`market_known_zero`，Python/JS 特征、预测、贡献、评价与择时审计共用）。历史用观察报价日代理，未来用已核实日历。
- 门槛：提前 30 日市场 MAE 较零变化至少改善 5%；上涨、下跌各至少 30 笔，两种行情的 MAE 均不超过各自零变化基准的 105%；票面 MAE 不差于原模型及零变化结构 0.2bp。通过者按票面 MAE、RMSE 选模。逐年、逐月、涨跌组披露误差、方向准确率和始终下跌基准。
- 发布从全部开发 receipt 重算选择并核验历史分母和报告，漏月、代码变动或不匹配均拒绝。

### 训练窗行情平衡（schema 8）

假设是原 Ridge 的下跌漂移使上涨保护失效。固定五组：原 Huber、零市场变化、原 Ridge、行情平衡 Ridge、行情平衡 Ridge 的 50% 收缩。开发边界 2023-01-01 至 2025-09-01，只有后两者可获选，原 Ridge 仅作控制。五组完成后停止，不据结果调整权重、特征或门槛。

每个直接提前期只读月初截止前已成熟的标签。以同起点五期限变化的均值定义上涨（≥1bp）、下跌（≤−1bp）和平稳。

- 上下行各至少 30 个起点时，原始权重 = 移动起点数 ÷（该组起点数 × 2），封顶 3，平稳权重为 1。再归一到均值 1，每个起点的五个期限各分 1/5。任一方向不足 30 个起点，则全部取均匀权重。
- 平衡版不去均值。50% 收缩同时作用于系数和截距，保持预测与归因相加一致。
- 它们是加权风险下的点预测，不是条件均值，也不是预期节约。

### 目标期限动态与曲线形状（schema 9）

五组：原 Huber、零变化、原 Ridge 三个控制，加 `tenor`、`tenor_shape` 两个 Ridge 挑战者，只有挑战者可获选。输入、开发边界、5 年窗口、alpha 和门槛同 schema 8。

- `tenor` 替换市场层原有的 5 个行业 AAA 3Y 状态，改用目标债券期限的 1/5/20 报价日变化和 20/60 日均线偏离。其余 9 个资金、国债和信用状态保留。`tenor_shape` 另加行业 10Y−1Y 斜率与曲率 `y3 − (7/9·y1 + 2/9·y10)`（bp）。
- 用 1/3/5/7/10Y 核心节点，先在原完整报价日时钟上计算，再无外推地插值到目标期限。缺节点、窗口不完整和区间外期限保持 NaN，不前填，不缩小评价分母。
- 日频计算通过 `industry_curve_dynamics` 注册组和 `build_feature_bundle()`，逐请求只读严格早于 origin 的报价。新列只进挑战者的市场层，发行溢价树中固定为零，三个控制不含新列。
- 主门槛为共同 195 笔 h30。另报精确 3Y 与非 3Y、业务期限桶、五个预测提前期、涨跌组，以及同训练窗常数。再报最差定价年和定价月、发行人配对区间。债券期限与预测提前期分别解释。

## 成熟样本外残差的票面校准

这是独立的校准变换研究，复用 schema 9 原 Huber 的 32 个月、923 行已验证预测。新协议另冻结校准源码、依赖和来源清单：

```bash
uv run python scripts/coupon_calibration.py register --source <原development目录> --source-root <保留原科学源码的工作树> --output <新研究目录>
uv run python scripts/coupon_calibration.py run --output <新研究目录>
```

须先提交科学源码。输出只有忽略目录中的协议、逐笔修正、池审计和聚合结果，不导出生产包。

- 候选 A：全提前期按事件等权的中位数统一平移。候选 B：各提前期独立中位数。残差 = 实际票面 − 原始未校准 Huber 预测，不递归使用修正后的误差。
- 每月初冻结。池内 origin 和存储成熟日期严格早于月初，成熟日期在前 365 自然日内。A 的每只债总权重为 1，同债已有 k 个提前期则各 1/k。B 的同债同提前期只取一行。累计权重恰为一半时取相邻残差中点。至少 30 个不同债券才启用，否则修正为 0。
- 从空池开始，不用训练集残差预热，不回填冷启动预测。五个提前期、冷启动和缺池事件都留在分母内。逐月审计成熟池的债券数、行数、权重、提前期构成、最晚日期和偏移。
- 历史回放只按存储成熟日期执行，原字段尚未证明真实披露时刻，不称真实事前检验。
- 门槛沿用 `candidate_report(calibrated, raw_huber, business_tenors=True)`：h30 MAE 至少改善 max(0.5bp, 5%)；绝对偏差恶化不超过 1bp；至少两年改善；其他提前期 MAE 恶化不超过 1bp；样本充分的组恶化不超过 2bp。
- 合格者按 MAE、RMSE、固定名称排序，不调用 schema 5 授权选择分支。披露按定价月和发行人聚类的区间（seed 42，2000 次）。
- 两个候选执行后停止，不追加窗口、收缩或主体细分搜索。
- 两候选没有独立市场层，不沿用市场分离门槛。当前只有 7/14/30/60/90 日样本外预测，没有 h0 和完整每日残差，因此不能推导每日日期排序或等待收益。门槛通过只表示可进一步验证，须独立前向验证和完整业务发布验收，不自动激活。

## 资源与检查点

CLI 在单进程、单线程、低优先级下运行，外部监督整个子进程树的 RSS，超过 2GiB 即停止并保留检查点。每完成 4 个月新拟合，用同一 PID 替换进程以释放原生内存，固定输入后读取已验证的检查点继续。不自动降低样本或配置。

代码、数据或配置变化默认拒绝续跑，应建新实验目录。纯资源修复若需复用旧缓存，须单独保留差异审计和重算等价证据，不能改哈希。

## 当前源码复现旧研究

结构拆分或训练实现漂移后，旧来源校验失败关闭。用以下命令登记只读旧来源、Git 源码版本、实际依赖、完整当前源码和输入/节点哈希：

```bash
uv run python scripts/register_reproduction.py --original-request <原development.json> --original-point <原point目录> --snapshot <原输入> --output <新目录>
```

源码须先提交。输出保存不可变的 `migration-inventory.json`、`smoke.json` 和 `development.json`。先用 smoke 协议验证单月，再在新目录完整执行原 19 候选及原时间边界。

- 不把旧检查点复制成新成绩，不以必须选回原模型为条件。逐月比较事件键、标签、成熟时点、预测、核心误差、训练诊断和择时路径，并明确新增的指标与诊断列。
- 之后 point 历史评价、严格加载、训练导出和完整 Python/JS 一致性都通过，当前 CLI 才可使用新证据。新来源拒绝旧发布证据，冻结选择被来源校验拒绝时不绕过。生产切换另走原门槛和发布核验。
- 重跑期间不得修改已绑定的源码、依赖、旧来源或输入，任何变化都拒绝续跑，须重新登记。报告证据、模板和文档更新不改研究身份。
