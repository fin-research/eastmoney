# 发行资料观察时间切片

这是独立的只读协议接入：不构建训练面板，不替换历史输入，不接入生产 Workflow。Data 的写入协议见 [发行观察](../../data/docs/modules/issuance-observations.md)。首次公开时间仍未知，完整评级、条款版本和全池后续修订未覆盖。给定最终发行条件的旧回放不能据此改称事前研究。

## 职责

- `online/observation-store.mjs`：只捕获已有 R2 adapter 的 `get/list`，限制指定实例和 Data 自有前缀，按页、按对象和累计限制读取。不提供写入、删除、任意路径或上游查询。
- `online/observation-contract.mjs`：校验 schema v1 的有限来源、规范请求及键、原发行日上下文、内容字节 SHA 和质量记录。用同一 JavaScript 规范化语言，共享测试样例由 Data 方生成，不用 Python JSON 重新编码内容哈希。
- `online/observation-slice.mjs`：显式接收 `instances`、带时区的 `cutoff` 和可选的原发行日 `bonds`。输出有限字段观察、原始状态、逐项来源、请求与字段覆盖、排除原因和实际读取元数据。不拼训练标签，不读数据库当前行。

## 截止与选择

- 实际收到响应的时刻、请求映射对象和内容对象的 R2 `uploaded` 都必须严格早于截止时刻。客户端 `archived_at` 只用于来源审计，不能替代真实持久化时间。R2 字节、服务端上传时刻、ETag、版本和大小均保留。对象在列举与读取之间变化则拒绝该观察。
- 请求集合只有在 manifest 自身也于截止前持久化，且记录与来源 / 结果逐项一致时，才称有限范围完整。manifest 缺失、损坏或晚到时保持 unknown，不用事后清单补写过去的完整覆盖。声明归档失败、记录或内容不可用都保留缺口。读取成功、Completed 或空数组不等于模型覆盖完成。
- 同来源、代码和字段取实际响应接收时间最新的观察。之后出现的 absent / null / empty、缺券、来源失败和隔离状态，不回退到旧的非空值。同刻同状态 / 值 / 上下文则合并出处，同刻更正或上下文冲突标为 ambiguous。
- 公告日保留为原始字段，不当作最终票面的首次发布时间。原发行日与调用方期望不一致时标明冲突，未知发行日不补造。
- 请求映射已验证但内容不可用时，保留有限上下文的不可用状态。CTR 失败、无数据、空表或遗漏先前代码时，对原日期范围内的旧字段建立可用性屏障。范围外不受影响，后续有效观察可解除。同刻缺失与旧值仍为歧义，不解释为债券被删除。请求集合为 unknown 或 partial 时，所有最新值保持不可用。`raw_observation` 和 `last_known_observation` 只保存历史事实供审计。
- 字节 SHA 基于实际收到的原始字节，BOM 和非规范编码不被静默剥除。读取预算逐 chunk 即时计入，后续大小、UTF-8、解析或校验失败也不退款。清理流的失败不覆盖硬预算异常。超额拒绝整个切片，不用截断部分代替。
- 输出只覆盖显式实例和有限字段，不证明全池、完整历史或真实首次公开时间。任何未知、缺失或 partial 都保留研究分母，不能靠删缺失记录取得更优成绩。

## 验收

`online/tests/observation-slice.test.mjs` 验证接口与失败边界。覆盖 Data 合成样例、日期 / 时区、晚到持久化、清单、哈希、跨实例、缺失 / 隔离 / 失败、冲突、分页、累计预算和禁止非读能力。规范样例的所有方版本与 SHA 在测试夹具的 provenance 文件。

本地 workerd / R2 验收只用合成对象，须标明 local synthetic。真实日常实例另验内容、时间、manifest 和抓取清单。离线包若无可追溯的服务端元数据，不能凭自填 `uploaded` 时间证明历史可得性。R2 `uploaded` 的含义见[官方参考](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。

传输错误、读取预算拒绝和无法获取真实 R2 元数据都作为未知证据保存，不转为空目录。

## 研究接入设计

以下是后续实现的固定设计，不是已执行的训练协议。实施前须另建研究版本，固定完整来源、实际实例清单、输入、预测登记和评价代码。

### 先验收观察覆盖，再接入成熟标签

第一阶段只回答：既有日常采集的有限响应是否完整归档，在指定系统截止时刻能否验证其状态和原始字节。研究单位是实例内的规范请求及其代码、原发行日和字段，不是全市场债券。

- 每日先按生产调度实例登记清单，保留未触发、失败、缺 manifest、空表、缺券、冲突和预算拒绝。不能从成功归档的对象反推实例。
- 按来源分别记录：
  - 请求数，以及成功、无数据、失败的响应数。
  - 归档成功与失败数，返回与缺失代码。
  - 字段状态、上下文冲突、有限范围可用数。

  请求总数仅在 manifest 可验证时算已知。缺 manifest、step 未执行或不可读时保持未知，不计零，不称完整分母。
- CTR 无返回不能推断没有发行，未调度不等于上游无数据。父批与二分叶批保留各自角色，不相加成独立债券数。跨日重复观察不扩大独立事件分母。
- 当前 CTR 在发行后查询近期发行，CSS 主要补齐资料，齐全后可能停止查询。这不是发行前候选池、全池持续修订记录或完整的评级 / 条款公告版本。即使覆盖验收通过，也不能用这份目录补出历史 h30 方案、恢复过去预测时点的债券清单，或证明“未更正”。

第二阶段才构造新的成熟标签输入：

- 发行事件键含债券代码和原发行日，日期纠错另登记，不覆盖旧事件身份。同一事件多个提前期的训练总权重仍为 1。
- 最终票面只用定价来源的 `TENDERFINALCOUPON`，定价日用 `TENDERDATE`，不从 CTR 的 `ISSUERATE_REFERENCE` 或公告日补造。
- 标签须同时满足三项才纳入：截止前已持久化的最新最终票面有效；定价与发行日期上下文一致；有限请求集合可验证。
- 成熟时点取相关接收、映射、内容及证明请求集合完整所依赖的 manifest 上传时刻的最大值，且严格早于重训截止。依赖多个实例清单时，所有清单的可得时刻都要计入。未知清单没有可用的成熟时点。
- 最新 null / empty / absent、缺券、失败、隔离、歧义或不可用状态不回退到历史非空值。声明的实例集合整体为 unknown / partial 时，所有最新字段不可用，不能删除失败实例来取得完整覆盖。
- 每次训练按截至当时的切片重新判定成熟集合，不把后来资料倒灌到旧训练月。系统观察时点是保守的可用证据，真实首次公开时间保持未知。

### 方案条件与未来标签分开冻结

- 方案条件含发行人、评级、期限、普通 / 次级、公私募和规模。它们须来自预测时点已登记的业务方案，或经独立验证的公开版本。每次修改创建新版本并保留实际登记时刻，不能用最终发行条件回填。当前观察目录不足以证明这些条件在发行前齐备。没有独立方案时只做覆盖研究，不生成可计入前向成绩的预测。
- 预测登记须在未来标签出现前保存模型 / 源码、输入与日历哈希、实际预测时刻、方案版本、预测窗口和关联规则。没有已知债券代码时，先登记发行人、债型、期限 / 方式、计划区间和匹配规则（唯一或多笔）。不事后挑选误差最小的同主体发行。实际匹配与未匹配都进台账，只有独立核实的事件身份可关联标签，无法唯一匹配的单列。
- 查看新评价结果前冻结可执行协议。协议含上海时区 h30 的自然日 / 精确时差定义、同事件重复预测的取样和方案变更处理。离线规则已在[台账](PROSPECTIVE_REGISTRY.md)中固定，真实接入和前向评价协议仍待冻结。
- 事后才能知道哪些登记符合 h30，但不据此重算或改写原预测。多方案版本、滚动预测或多个提前期不冒充独立债券，须分别披露登记数、匹配数、独立事件数和失败原因。取消、条件改变、未发行或未成熟的登记保留状态。
- 对照用接入时独立冻结并验收的原 Huber 方法，先固定月度重训和包有效期规则，不永久复用会到期的当前包。双方取得相同的预测时点和方案信息，不用未来评级 / 条款给一方优势。
- 先通过工程、真实输入和覆盖验收，再积累前向证据：至少 3 个定价月和 30 笔合格 h30 事件。不据验收结果重选模型或放宽门槛。票面点预测、市场代理择时和真实融资收益分开报告，稳健中心不支持预期节约字段。

### 验收阶段

| 阶段 | 必须取得的证据 | 当前状态 |
| --- | --- | --- |
| 真实归档 | 部署后的日常实例、发行 step、manifest / 完整请求集合、真实 R2 字节及服务端元数据 | 有限现存内容已核；完整枚举、Worker 元数据及早期 step 待验收 |
| 新标签面板 | 已验真实捕获、截止前成熟集合、全部排除 / 缺失台账、冻结来源与分母 | 未实现，不沿用旧历史标签可用日 |
| 事前方案与预测 | 独立方案版本、事前登记、固定匹配规则、同信息对照 | 离线登记与审计已实现；真实独立方案来源、可信时间锚待验收 |
| 前向评价 | 至少 3 个定价月和 30 笔合格 h30 事件，完整登记 / 事件台账和既定统计门槛 | 待积累；合成验收和旧回放不计入 |

验收不触发付费 Workflow、不扩大 Choice 范围、不恢复写库、不变更生产模型指针。本地台账全为 `local_unanchored`，没有独立持久化时间证明，不计入 3 个月 / 30 笔的真实前向门槛。

### 已核验的信息不足

以下结论来自只读核查，原始证据在忽略的 `outputs/` 目录，仍须遵守：

- Data `/primary-issues` 返回最终票息、计划金额和发行日期，但无稳定代码、评级、公告时间或版本，且不给分页完整性。`/broker-bond-registrations` 只有更新日期和项目文字，通知编号常缺。历史日期参数只筛当前返回的记录，不证明字段在历史预测起点可得。当前票息或最终条款不得倒灌训练。
- 既有冻结面板已含 11 项供给、发行只数、净融资、偿付及资金交互特征。这些回看指标不是新增的计划供给。
- Dashboard 保留的负债周报对象有保存时刻之后的有限研究价值。报告日不是抓取时刻，同日对象可覆盖，当前索引不证明已删除或曾有的旧版本。没有核验到覆盖 2023—2025 年开发期的计划版本，不接入旧回放。
- 对六个固定样本检查一手公开材料：发行公告和票面利率公告的日期，都比各自 h30 起点晚 25—29 日。没有一例建立起点前的本期计划完整链。官方文书能确认本期与注册批文的关系，但不能倒推 h30 时的本期排期、品种回拨或实际规模。这是小样本结论，不是总体覆盖率。
- [上交所债券项目信息平台](https://bond.sse.com.cn/bridge/information/index.shtml)提供项目 ID、发行人标识和分阶段文件，可作为未来信息捕获的候选。其历史完整项目集合、撤回 / 未发行分母、全部修订版本，以及项目到单期债券的起点前关联，均未验证。
